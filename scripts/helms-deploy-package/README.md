# Helms Executable Deployment Package

This package is generated by:

```bash
bash scripts/create-helms-deploy-package.sh
```

It contains:

- `frontend/dist/`: prebuilt Helms branded frontend assets.
- `frontend/Dockerfile`: Nginx image for serving the static frontend.
- `frontend/nginx.conf.template`: SPA fallback plus `/api`, `/ws`, `/p`, and optional `/minio` reverse proxy.
- `backend/`: Clawith backend source from the generated Helms worktree.
- `docker-compose.yml`: PostgreSQL, Redis, backend, frontend, and optional MinIO.
- `.env.example`: environment variable template.
- `CLAWITH-LICENSE`: upstream license copy.

## Run

Make sure Docker Desktop or OrbStack is running before starting the package:

```bash
docker info
```

Make sure the frontend port is free:

```bash
lsof -nP -iTCP:3008 -sTCP:LISTEN
```

If `3008` is already used by an old Clawith/Helms process, stop that process first or change `FRONTEND_PORT` in `.env`.

```bash
cp .env.example .env
```

Edit `.env` before production. At minimum replace:

- `PUBLIC_BASE_URL`
- `CORS_ORIGINS`
- `SECRET_KEY`
- `JWT_SECRET_KEY`
- `POSTGRES_PASSWORD`
- `DATABASE_URL`

Clawith `v1.11.x` uses the Durable Agent Runtime. The deployment package keeps
it enabled and initializes both Alembic and LangGraph checkpoint schemas during
backend startup. Before using multi-Agent group planning, configure enabled
platform model UUIDs for:

```text
MULTI_AGENT_PLANNING_MODEL_ID=
MULTI_AGENT_COMPACT_MODEL_ID=
```

Leave them empty for initial single-Agent validation, then configure them from
Platform Settings before accepting group collaboration traffic.

If Docker Hub is unreachable, set these in `.env` to images from your registry or mirror:

```text
HELMS_PYTHON_BASE_IMAGE=python:3.12-slim
HELMS_NGINX_BASE_IMAGE=nginx:alpine
HELMS_POSTGRES_IMAGE=postgres:15-alpine
HELMS_REDIS_IMAGE=redis:7-alpine
HELMS_MINIO_IMAGE=minio/minio:RELEASE.2025-04-22T22-12-26Z
```

For a local smoke test only, if `python:3.12-slim` or `nginx:alpine` cannot be pulled but compatible images already exist locally, you can point `.env` at those local tags, for example:

```text
HELMS_PYTHON_BASE_IMAGE=python:3.11-slim
HELMS_NGINX_BASE_IMAGE=nginx:latest
```

Production deployments should use pinned images from a reliable registry or internal mirror.

If backend image build times out while downloading Python packages, set a reachable pip mirror:

```text
CLAWITH_PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple
CLAWITH_PIP_TRUSTED_HOST=mirrors.aliyun.com
```

Start with local file storage:

```bash
docker compose up --build -d
```

If apt or pip mirrors fail transiently, retry the same command. Docker build cache will reuse completed layers.

Start with bundled MinIO:

```bash
sed -i.bak 's/^STORAGE_BACKEND=.*/STORAGE_BACKEND=s3/' .env
docker compose --profile s3 up --build -d
```

Check service status and health:

```bash
docker compose ps
```

```bash
curl -f http://127.0.0.1:3008/api/health
curl -fsSI http://127.0.0.1:3008/login
curl -fsS http://127.0.0.1:3008/login | grep 'Helms AI数字员工工作台'
curl -fsS http://127.0.0.1:3008/login | grep '/helms/favicon.svg?v=20260622'
curl -fsS http://127.0.0.1:3008/helms/logo.svg | head
```

Open:

```text
http://127.0.0.1:3008
```

If browser access to `127.0.0.1` is affected by local proxy or browser policy, try:

```text
http://localhost:3008
```

Inspect logs:

```bash
docker compose logs --tail=120 backend
docker compose logs --tail=80 frontend
```

Stop services while keeping data volumes:

```bash
docker compose down
```

Remove local test data volumes only when you intentionally want a clean reset:

```bash
docker compose down -v
```

## Notes

- This package is a deployment convenience for Helms 0.1. It does not add new backend APIs or database models.
- Regenerating the package preserves an existing `.env` and `ss-nodes.json` in
  the package directory. They remain local runtime files under ignored `.work/`.
- The backend still runs Clawith runtime. Helms branding/localization is applied to the frontend.
- The compose file mounts `/var/run/docker.sock` and grants elevated container privileges to preserve upstream local sandbox behavior. Review this before production exposure.
- Use HTTPS at the external reverse proxy or load balancer.
- Back up PostgreSQL and either `/data/agents` or the configured object storage
  bucket before upgrading from Clawith `v1.10.x`; the `v1.11.x` startup performs
  schema and LangGraph checkpoint initialization.
