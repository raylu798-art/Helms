# 07 - Helms 0.2 候选 Backlog

本文件只记录 Helms 0.2 候选方向，不代表当前已经进入实现。Helms 0.2 的前提是保持 Clawith 上游干净，继续优先使用 Overlay + Patch 机制，避免深度 fork。

## 1. 候选目标

Helms 0.2 建议定位为轻量产品包装版：

- 更完整的中文术语覆盖。
- 默认数字员工模板文案。
- 演示数据初始化。
- 中文帮助说明。
- 私有化部署说明。
- 客户演示脚本。

## 2. 候选任务

优先级建议：

| 优先级 | 候选任务 | 说明 |
|---|---|---|
| P0 | 中文覆盖扫描报告 | 扫描核心路径残留英文，形成覆盖清单，不做全局替换 |
| P0 | 默认数字员工模板 | 准备销售、运营、客户成功等演示岗位文案 |
| P0 | 演示脚本 | 输出客户演示路径、话术和风险提示 |
| P1 | 演示数据初始化 | 设计 mock/seed 机制，优先不侵入真实后端 |
| P1 | 私有化部署说明 | 整理环境变量、构建命令、部署注意事项 |
| P2 | 中文帮助说明 | 补充用户侧概念说明和常见问题 |

## 3. 继续禁止的事项

除非后续明确进入深度功能阶段，否则 0.2 仍不默认实施：

- 数据库模型变更。
- 后端 Agent Runtime 改造。
- 权限、Sandbox、A2A、Crew、Aware 深层改造。
- 新增任务中心、产物库、模型网关。
- 删除 Clawith attribution 或第三方开源声明。

## 4. 进入 0.2 前置条件

进入 0.2 前应先满足：

- Helms 0.1 build、smoke test、visual check 可复现。
- `vendor/clawith` 干净。
- `.work/` 不进入 Git 状态。
- 0.2 每个任务都能拆成独立 overlay、patch、script 或 doc 改动。
