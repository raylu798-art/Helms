# 00 - Helms 产品定位说明

> 当前阶段目标：**Helms 0.1 = 基于 Clawith 的品牌化、汉化、可持续更新白标版本**。  
> 当前阶段不做深度功能改造，不改数据库，不改后端 Agent Runtime，不改 A2A/Crew/Aware/Sandbox 等核心能力。

---

## 1. 产品名称

**Helms**

推荐中文表达：

- **Helms AI数字员工工作台**
- **Helms 企业AI数字员工工作台**
- **Helms 数字员工协作平台**

第一阶段建议使用：

> **Helms AI数字员工工作台**

---

## 2. 一句话定位

**Helms 是基于 Clawith 能力底座进行品牌化与中文企业化包装的 AI数字员工工作台，第一阶段聚焦白标化、汉化和演示交付，不做底层功能深度改造。**

---

## 3. 当前阶段产品策略

Helms 当前不是从零自研 AI Agent 平台，也不是立即深度改造 Clawith，而是采用：

```text
Clawith 上游能力底座
  +
Helms 品牌化覆盖层
  +
Helms 汉化覆盖层
  +
Helms 构建/更新/交付脚本
```

核心原则：

1. **Clawith 负责功能演进**：Agent、Workspace、Aware、Crew、Tool、MCP、A2A 等能力尽量跟随上游。
2. **Helms 负责产品包装**：品牌、中文术语、企业化文案、部署说明、演示口径。
3. **改造尽量独立**：Helms 自有内容放在 `helms-overlay/`、`patches/`、`scripts/`、`docs/`。
4. **不污染上游源码**：Clawith 作为 submodule 管理，原则上不直接修改 `vendor/clawith`。
5. **先验证市场反馈**：先做可演示、可展示、可试用的中文白标版，再决定是否进入深度功能改造。

---

## 4. 产品阶段定义

## Helms 0.1：品牌化与汉化白标版

目标：

> 让 Clawith 在用户感知层变成 Helms：产品名、Logo、Favicon、页面标题、核心导航、核心演示路径、基础中文术语。

Helms 0.1 只解决：

- 品牌展示；
- 中文化体验；
- 企业软件表达；
- 构建脚本；
- 上游更新机制；
- 冒烟测试；
- 演示可用性。

---

## Helms 0.2：轻量产品包装版

目标：

> 在不重写底层的前提下，进一步增强中文体验、默认模板、演示数据、部署说明和客户试用体验。

可能包含：

- 更完整的中文术语覆盖；
- 默认数字员工模板文案；
- 演示数据初始化；
- 中文帮助说明；
- 私有化部署说明；
- 客户演示脚本。

---

## Helms 0.3 以后：谨慎进入轻功能改造

只有在 Helms 0.1/0.2 验证有效后，再考虑：

- 轻量任务入口；
- 企业知识库包装；
- 模型配置优化；
- 私有化部署增强；
- 安全基线检查；
- 行业模板。

---

## 5. 当前阶段不做什么

Helms 0.1 明确不做：

| 不做事项 | 原因 |
|---|---|
| 不改数据库模型 | 避免上游合并冲突 |
| 不改后端 Agent Runtime | 风险高，影响核心功能 |
| 不改 A2A/Crew/Aware | Clawith 更新频繁 |
| 不改权限体系 | 安全风险高 |
| 不改沙箱/代码执行 | 需要专项安全设计 |
| 不新增任务中心 | 会引入新业务模型 |
| 不新增产物库 | 会引入新数据闭环 |
| 不重构知识库 | 工程量大 |
| 不做模型网关 | 会影响模型调用链 |
| 不全量删除 Clawith 痕迹 | 开源合规要求必须保留 attribution |

---

## 6. 目标用户感知

Helms 0.1 交付后，用户应该感受到：

1. 这是一个名为 **Helms** 的产品；
2. 主要界面是中文；
3. AI Agent 被表达为 **数字员工**；
4. Workspace 被表达为 **工作区**；
5. Tool/Skill 被表达为 **工具/技能**；
6. 产品更像企业软件，而不是开发者开源项目；
7. 功能上仍保留 Clawith 原有能力。

## 8. Helms 与 Clawith 的关系

推荐对外表述：

> Helms 基于开源项目 Clawith 进行品牌化、汉化和企业场景包装，并在遵守开源许可证的前提下进行分发和交付。

不建议表述：

- “Helms 完全自主研发底层系统”
- “Helms 与 Clawith 无关”
- “Helms 删除了 Clawith 开源来源”
- “Helms 已完成深度自研 Agent OS”

---

## 9. 当前阶段成功标准

Helms 0.1 成功，不看功能多不多，而看以下结果：

1. 能稳定构建 Helms 白标版本；
2. 登录页、标题、Logo、核心导航显示 Helms；
3. 核心演示路径基本中文；
4. `vendor/clawith` 保持干净；
5. Clawith 更新后，Helms overlay/patch 可重新应用；
6. 保留开源许可证和必要 attribution；
7. 客户看演示时，不会明显感到这是一个未包装的英文开源项目。

---

## 10. 当前阶段一句话总结

**Helms 0.1 的本质是：在不深改 Clawith 的前提下，通过 Submodule + Overlay + Patch 机制，把 Clawith 包装成可持续更新、可中文演示、可品牌展示的 Helms AI数字员工工作台。**
